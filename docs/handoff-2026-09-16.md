## 4. Правила, которые нельзя нарушать (из памяти/профиля пользователя)

- **Пуш и деплой — только по явному слову пользователя.** Пуш в `develop` триггерит CI + деплой стейджа.
- **Hermes — управляющий оркестратор** («прораб»): решения, ТЗ, верификация, арбитраж. Holix/OpenHands/dsh — исполнители.
  Тривиальное → Hermes; сложное → Holix; массовое → OpenHands; дизайн → dsh; один исполнитель на файл.
- **Перед любым CI-прогоном E2E** освободить `:3000`/`:5173` и убрать CI-контейнеры
  (`e2e-pg`, `e2e-redis`, `backend`, `mobile-backend`, `k6-*`, `dast-*`). В джобах теперь есть fail-fast
  проверка портов и уборка после джоба — но dev-стек гасит человек.
- **Планирование** («сделай план работ») идёт флоу superpowers:
  `brainstorming → writing-plans → executing`. Навыки namespaced, грузить явно:
  `skill_view("superpowers:brainstorming")`.
- **Доки проекта**: без упоминаний OAuth/OIDC (валит `docs-auth-check`), вся дока — в `docs/`,
  вход — `docs/index.md`.
- **Секреты не печатать.** Токен git remote — `x-access-token:***`, пароли БД из `.env` не читаются.
- **Не совмещать тяжёлые pnpm-операции с CI-ранами** (self-hosted раннер на той же машине).
- `docs/archify/*.html|.png|visual-check` не коммитим.
- Вопрос (clarify) = пауза: ждать ответа, ничего не начинать.
- При старте сессии — чеклист `studio-readiness.sh` с показом вывода.
- Верификация backend — `tsc --noEmit` как CI-путь, НЕ `nest start` (падает на плагинах).

## 5. Инфраструктурные грабли (проверено на живых прогонах)

- **Раннеры теряли связь с GitHub**: джоб висит, `updated_at` не меняется, в worker-логе
  `BrokerServer: SocketException (125): Operation canceled`.
  Лечение: `systemctl --user restart actions-runner.service actions-runner-2.service`
  (сервис второго раннера — с дефисом: `actions-runner-2`).
- **Зависшие джобы занимают раннеры**: после отмены рана воркеры продолжали жить 2–4 часа и
  продлевать аренду, из-за чего новые раны висели в `queued`. Лечится тем же рестартом.
- **Рестарт раннеров убивает уже взятые джобы** → они помечаются `cancelled`
  (в логе `exit code 143`, «runner has received a shutdown signal»), и ран уходит в `cancelled`.
  После рестарта нужно перезапустить такие джобы: `POST /runs/<id>/rerun-failed-jobs`
  (для отменённого рана это тоже работает, HTTP 201).
- **GitHub API периодически отдаёт пустые ответы** (сеть) — оборачивать вызовы в retry-цикл.
- **Монаitor-скрипты**: `/tmp/mon-run.py <RUN_ID>`, `/tmp/mon-run2.py <RUN_ID> <минут>`
  (кладут итог/вывод в лог, завершаются по ALL_JOBS_DONE + GREEN/NOT_GREEN).
